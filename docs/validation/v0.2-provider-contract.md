# v0.2 developer provider contract — 2026-11-02

Public activation remains disabled. Existing local developer access authorizes these checks; it does not establish redistribution permission. No restricted history/leaderboard endpoint was called. No raw player response, credential, player name/UID or actual RP is included in committed fixtures or this report.

## Documentation and observed structure

The [official provider portal](https://apexlegendsapi.com/) was re-read on 2026-11-02. It documents `/bridge` version **5** as currently supported; PC/PS4/X1 accept names and UIDs, while SWITCH accepts UID only. PC name lookup requires the linked EA/Origin name. Repeated synchronization should use UID. `/predator` documents RP cutoffs and Master counts across four platforms. Initial standard limit is five requests/second across APIs, a ceiling rather than a refresh target. Its error table defines 403 unauthorized, 404 missing player, 410 unsupported platform, 429 limited and 405 upstream failure.

Authorized private in-memory structural discovery returned **HTTP200** for `/bridge?version=5` name lookup and `/predator`. These were low-rate requests through the existing owner-only key, without saving raw responses or logging identities. Observed bridge fields were `global.uid`, `name`, `platform`, `level` and `global.rank.rankScore`, `rankName`, `rankDiv`, `ladderPosPlatform`, `rankedSeason`. Profile observation time is successful retrieval time; no undocumented upstream observation timestamp or split is inferred. Unknown rank labels survive; malformed nullable statistics become unknown, never zero. The parser rejects mismatched UID/platform.

Observed Predator structure is `RP.{PC,PS4,X1,SWITCH}.{val,updateTimestamp,totalMastersAndPreds,foundRank,uid}`. The adapter stores only platform, validated `val`, upstream epoch-second timestamp and the **combined Master + Predator population**. It discards upstream player UID and all legacy AP data. `foundRank` was not 750 for every platform: the UI must describe the reported dynamic cutoff without guaranteeing placement. Old source timestamps remain old even after a successful fetch. No official season rank-threshold table was verified or bundled.

Unavailable rank fields do not reveal whether a profile is private, unranked or temporarily incomplete. The app must show unavailable/private information honestly rather than assert a privacy setting unsupported by this contract.

## Implementation and tests

`ApexRankedParser` normalizes this observed structure. `ApexStatusRankedProvider` uses the existing no-redirect/no-logging Ktor client and runtime Authorization supplier, bounded 512KiB streaming bodies and fixed safe errors. A map-only approved gateway cannot silently activate profile access. Switch name searches fail before requesting. HTTP410 is unsupported-platform rather than a fabricated account deletion. Error bodies are never exposed or persisted.

Synthetic deterministic tests cover valid/nullable/malformed/unknown ranks, identity/platform mismatch, all four UID platforms, name/UID request routing, version/header-only auth, Switch-name refusal, Predator RP/source timestamp/population, partial/future source fields, status errors/Retry-After, oversized JSON, timeouts, cancellation and safe exception redaction.

`RankedLiveContractTest` is Android-host-only and opt-in: `APEX_STATUS_RANKED_LIVE_TEST=1`, existing `APEX_STATUS_KEY_FILE`, and external owner-only `APEX_STATUS_PLAYER_FILE` containing a chosen public `name` and `platform`. It resolves name → UID, repeats by UID, then validates Predator through the production adapter, with one-second gaps. It prints no profile identity, RP, raw body or key and persists none. Ordinary suites skip it. Execution results are recorded in the main v0.2 report after integration.

No iOS compilation, tests, simulator, signing or Apple tool was attempted. Shared source is implemented for KMP; Apple validation remains deferred under ADR0007.
