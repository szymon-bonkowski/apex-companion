## Windows capture architecture and acceptance boundary

C#/.NET10 WinForms uses Windows.Graphics.Capture, explicit system selection and documented HWND interop for one uniquely matched visible Apex-title window. The returned display picker item is never directly captured; no desktop fallback, injection, hooks, process-memory access, drivers, protected packets, game files, private authentication endpoints or gameplay inputs are used. Capture/listener start disabled, STOP/close cancels capture, unsupported dimensions are checked before allocation/recreation, and errors halt processing. Title matching is not game-process authentication, and documented Microsoft APIs do not establish EA/anti-cheat approval.

Default sampling is2seconds (UI range1–10seconds), one OCR job at a time, normalized image regions, processing width capped1920 and bounded local Tesseract stdin-PNG/TSV with cancellation/timeout. Frames/video/raw OCR names are not persisted or synchronized. The parser/layout ID is `english-prototype-v1`; it is not a validated current Apex layout. Mode/map/legend and other unsupported values remain unknown.

The testable state machine requires observed gameplay spanning20seconds followed by3result readings over at least2seconds before creating a stable event. Repeated result frames update that event; temporal contradictions clear fields; loading/spectator/session summaries create no result; startup results cannot arm tracking; out-of-order frames are ignored. A real automatic acceptance/atomic queue path is implemented and tested with an explicitly synthetic approved rule across2successive games. It requires a distinct transition, known repeatedly read mode, approved layout, repeated high-confidence fields and no contradictions. **Production approved layouts are empty, with no runtime override.** Real-world autoacceptance remains disabled.

The local unsigned self-contained package is `companion/artifacts/apex-companion-capture-win-x64-dev.zip`. Tesseract/English data are external trusted installation requirements. The utility supports independent scope or explicit `--uid <digits> --platform PC|PLAYSTATION|XBOX|SWITCH`, with separate per-identity private directories. Console capture is not implemented merely because a console identity can label a journal. Windows mutex behavior, WGC/COM runtime, ordinary-window capture, Apex presentation modes and game overhead have not been executed here.

## Match schema, storage and statistics

MatchRecord schema1 includes stable ID, optional exact UID/platform, mode, nullable map/legend/kills/assists/damage/placement/RP delta, UTC timestamp and timestamp source, original MANUAL/SCREENSHOT/WINDOWS_CAPTURE, REVIEW_REQUIRED/AUTO_ACCEPTED/USER_CONFIRMED, immutable event/parser identity, known-field confidence and revision. Defensive numeric bounds are import/storage limits, not asserted official game limits. Observed capture time is not invented game duration/start time. No RP observation interval is converted into a match.

The separate `matches-v1.json` has a16MiB/10000-record bound, at most8companion cursors and bounded deletion tombstones. Native atomic writes publish only after commit; corrupt/future/oversized journals remain read-only with original bytes retained. There is no silent trimming. Original normalized machine records survive corrections; replay cannot overwrite user-confirmed edits. Deletion keeps current-device replay suppression. Unreadable-store reset/recovery is an external recovery/compatible-version limitation, not an in-app silent reset.

Existing4MiB `ranked-history-v1.json`, RP observations, sessions, goals, current profiles and global caches are not migrated into the new store. Match-only portable format `APEX_COMPANION_MATCH_BACKUP`/schema1 contains records+normalized originals with explicit preview/confirmation. The existing v0.3 private-history/settings archive remains separately supported. Each archive has one atomic logical merge; a combined two-store atomic restore is not claimed. Match archives contain no pixels/video, credentials, pairing/network/capture configuration, native paths, cursors or tombstones. Conflicting IDs/events reject the whole merge; exact repeated imports are no-ops.

Shared Matches UI provides list/detail, mode/map/legend/source/quality filters, explicit manual review, duplicate warnings, correction preserving original source/event and separate match backup/deletion. Statistics default to USER_CONFIRMED; including AUTO_ACCEPTED is explicit and labeled. Kills/assists/damage/placement/RP use their own known-value denominators; unknowns never count as zero. Map/legend groups follow the same policy. REVIEW_REQUIRED contributes to no aggregate. Optional explicit match-to-session association/reconciliation UI is not implemented; no association or match count is inferred from sessions/RP gaps.

## Pairing, synchronization and privacy

Explicit private IPv4 LAN HTTPS uses an out-of-band exact SHA256 DER certificate pin plus random256bit bearer token, companion ID and configured player scope. Android keeps normal hostname/SAN/date checks in addition to the pin; iOS source uses pinned trust-anchor validation and the existing hostname policy. Redirects, public/non-HTTPS endpoints, unauthorized devices and foreign identities are rejected. Secrets use desktop current-user DPAPI, Android non-exportable Keystore AES-GCM and iOS ThisDeviceOnly Keychain. No credential is portable backup data.

Accepted records remain in the durable PC journal. The phone pulls at foreground/manual sync and every30seconds only while STARTED/paired; at most100records/1MiB per batch and20batches per attempt. Records+cursor commit before ACK. Offline/retry/failed ACK preserve records, deduplicate IDs and retain edits. No instant mobile background-delivery guarantee. One paired credential/device is supported; explicit new pairing rotates/revokes the previous token. **Start/resume paired local sync preserves the token/certificate after PC restart**, verified by portable tests and another actual native Android TLS/auth/replay run against the restarted Linux server without re-pairing. Unpair revokes remotely when reachable, clears local credentials and explains the offline PC-revocation step.

Android17 LAN permission is requested only on explicit pairing; denied/revoked access fails before a LAN request. No new gallery/camera/blanket-storage permission, scheduler, provider polling, API credential, public game route, cloud, advertising, payment, account or analytics feature was added. Existing provider/public release gates remain unchanged. No AGPL OverTrack code is incorporated. Original source is MIT; .NET/runtime/test SDK notices and Windows SDK terms are recorded; xUnit is Apache2. Tesseract Apache2/Leptonica BSD-style runtime/model binaries are not bundled; any future installer must audit its chosen Windows package/transitive notices.

## Remaining work and exit decision

Primary Windows/Apex automatic capture is not verified: obtain owner-approved rights-cleared real results/negative regions, separate tuning/held-out sets, measure classifier/each field across resolution/scaling/language/UI changes, execute ordinary-window then permitted actual Apex WGC tests, profile game overhead, and demonstrate successive real matches synchronizing to a phone without per-match interaction. Only then may an approved versioned layout enter production acceptance. Unknown/black frames do not create recognized matches; protected-capture diagnosis still needs Windows testing. The [Windows procedure](../WINDOWS_COMPANION.md) specifies this boundary.

Other unfinished work: native mobile OCR engine/quality, desktop installer/signing/archive/pruning and credential/interface recovery polish, optional session association UI, physical-device/full accessibility checks and Apple validation. iOS source is **Implemented — Not Verified**; no Xcode, Swift compilation, KotlinNative build, simulator or signing tool was run. Deferred iOS verification alone is permitted by ADR0007; the primary automatic-capture gate remains unmet. **Do not mark v0.4 complete or publish it as a verified automatic tracker.**
