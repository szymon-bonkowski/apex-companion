## Schema, migration and transactional guarantees

`ranked-history-v1.json`, schemaVersion1 owns recording consent (default off), observations, context confirmations, sessions, import markers and portable goal/manual settings. Existing v0.2 profile v1 and global caches remain readable and separate. On first valid initialization, independent v0.2 goal/manual/source fields are copied once; thereafter the history settings are authoritative and override legacy fields on restart. Confirmed import changes history and restored settings with one atomic whole-record commit. No provider/current/global cache is restored or overwritten by an import. Corrupt/future records remain read-only and original bytes survive initialization; explicit deletion retains readable independent settings, including recoverable legacy fallback. Newer settings inside a damaged authoritative file require an external backup for recovery.

Bounds: 4 MiB UTF-8, 4000 observations, 500 sessions, 500 confirmations, 100 import markers. Strict IDs, ASCII numeric UID/platform, BR mode, source, RP0..1,000,000,000, positive UTC seconds through year9999, current-time/export-time chronology, unique IDs and cross-record anchor/context ownership are validated. Deep nesting is bounded before parsing. Capacity failures retain all existing records; no automatic trimming. Platform writes precede state publication; a bounded noncancellable commit pairs durable state and memory when the initiating screen is canceled. Session summary formulaVersion1 persists classification, nullable RP/window, time/RP completeness and a safe explanation, validated against immutable evidence on decode. Android AtomicFile interruption recovery is tested; Foundation atomic/file-protection behavior awaits Mac/device validation.

Backup format `APEX_COMPANION_PRIVATE_BACKUP`, schemaVersion1 contains batch ID, export time and allowlisted user settings/history. Exports omit recording activation/current confirmation/import markers. They contain no keys/auth/configuration, provider caches/responses, names, paths, screenshots, widget instances or diagnostic logs. Provenance in an unsigned user backup is metadata, not independent upstream authentication. Import validates before preview, requires user confirmation, revalidates against current identity/state and commits once. Duplicate IDs/imports are idempotent; conflicting records, invalid/future/oversized/malformed files or overlapping active sessions reject without partial changes. Reimporting an older ACTIVE record does not reopen its locally completed session. With a linked profile every imported provider identity must match exactly; unlinked restores archive multiple segregated identities and never link them. Imported confirmation is not activated; recording remains under current user control.

## Observation and session semantics

Provider events are recorded only after a validated successful profile refresh is durably accepted. Cache reads/recomposition/widget rendering/errors/stale reuse/null RP create no observations; exact event IDs deduplicate while equal RP at a later timestamp remains evidence. Manual saves retain USER_RECORDED provenance with no player identity. Provider/background samples do not invalidate unrelated manual context/sessions.

The current parser deliberately leaves split null. Users explicitly confirm exact season/split, labeled USER_CONFIRMED; known provider season must agree. This affects future samples and creates a new context ID/baseline. Unknown history is preserved without deltas. Provider confirmation expires after a >24-hour gap or no samples since confirmation; season disagreement and suspicious discontinuities require review. An adjacent absolute change >1000 RP quarantines that derived interval as a conservative heuristic, not a game/reset rule. Ordinary -100 RP is valid. Immutable RP is never rewritten. Late observations sort by UTC then stable ID; interval calculation is deterministic. Lines do not span context/identity/source/unknown/quarantined boundaries or long gaps. Match counts, wins, kills, damage, placement and per-match RP are never inferred.

One session can be active globally. Start uses a real valid available anchor at most five minutes old and creates no observation. Local stop works without network and may lack a distinct end sample. Active ID/start/anchor survive restart; explicit identity/source/context/recording changes close the active session as UNCERTAIN. Results: OBSERVED for compatible provider anchors; MANUAL for compatible manual anchors; PARTIAL for missing/distinct-unavailable anchors; UNCERTAIN for incompatible/interrupted windows. RP unknown is nullable, never fabricated zero. A genuine later equal-RP pair may yield zero. Multi-sample accumulated session RP can exceed the single-interval anomaly threshold. User-selected duration and actual observation window are displayed separately. An imported active session retains its start; subsequent profile/context changes can close it uncertain rather than assert continuity.

## Privacy, security and release review

History is private and opt-in, never uploaded or shared automatically. UID/platform appear only in private provider history and user-selected backup, not widgets. Disconnect hides retained identity history; another player cannot see it. Confirmed deletion clears all history/context/session/import markers and turns recording off, preserving independent goals/manual RP, current profile and Maps/Predator caches. External backups remain user-owned.
