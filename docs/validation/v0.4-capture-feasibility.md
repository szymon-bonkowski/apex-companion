# Capture feasibility and implementation decision — 2026-11-03

Decision: optional C#/.NET10 WinForms utility, Windows.Graphics.Capture selected-window HWND, local Tesseract5, portable .NET recognition/state/queue and an opt-in private HTTPS server. This is implemented source, not proof of live Apex capture. [ADR0009](../adr/0009-windows-match-capture.md), [setup/verification](../WINDOWS_COMPANION.md).

| Candidate | Evaluation and decision |
|---|---|
| Windows.Graphics.Capture | Secure system selection, visible border, documented selected-window interop, Windows10/11; adapter targets1903+. Check IsSupported, create for unique selected HWND, stop if blocked. Chosen. Real Apex presentation modes/GPU compatibility unverified. |
| GDI BitBlt/PrintWindow | Ordinary documented APIs but game rendering/occlusion behavior uncertain; no benefit sufficient to justify alternate capture path. No fallback bypass shipped. |
| Desktop Duplication | Documented DXGI full-display surface, broader privacy scope than selected-window requirement and more handling overhead. Rejected for this slice. |
| Windows.Media.Ocr | Local OS engine, but desktop deployment/package identity and installed language dependencies complicate unpackaged utility; no Linux engine parity. Not selected. |
| Tesseract5 | OSS Apache2 engine, local CLI/stdin image to TSV, field confidence and bounded timeout; Linux/Windows engine availability and straightforward original parser tests. Chosen, external executable+English data required. OCR confidence is not a calibrated correctness probability. |
| PaddleOCR | OSS direction, but larger inference/model/runtime deployment and tuning burden without representative fixtures. Not selected. |
| OverTrack | Useful conceptual image→classification→regions→temporal aggregation reference; AGPL code is not imported/copied/linked and no compatibility decision to include it was made. |
| Overwolf/paid/cloud OCR | Adds unwanted distribution/privacy/service requirements. Not used. |

The capture adapter keeps at most one OCR job active, samples every2seconds by default (configurable1–10), scales OCR processing width to1920, uses normalized regions, discards raw frame/image buffers and stops on cancellation/error/window close. This limits work structurally; **no measured Windows/game overhead claim** follows. Screen state/classification and field normalization are separate interfaces. Parser english-prototype-v1 recognizes a deliberately narrow English label layout, not a validated season/UI. Actual mode/map/legend coverage is unavailable in the real game. Defensive limits reject unsupported resolution, malformed values or significant unknown UI; hidden fields remain null. No duration/win/match boundary is inferred from RP.

Persisted state/IDs plus observed gameplay and repeated timed result frames prevent startup result replay and repeated/alt-tab result multiplication. Temporal contradictions clear the affected field and block automatic acceptance. A real policy stage can autoqueue approved evidence, tested with a synthetic-only rule; Production registry is empty and there is no runtime override. Windows source crosscompilation and synthetic offline tests do not satisfy Windows live/Apex verification.

## Measured corpus

Only10original synthetic typography/geometric fixtures are available:4results,6non-results at1280×720,1920×1080,2560×1440 inputs and cropped/scaled regions. No game artwork, player names or user recordings. No model training/calibration was performed, and **real Apex fixtures=0; held-out real fixtures=0**. They are regression fixtures, not independent validation of game performance.

Missing unsupported fields stay null. No real mode/map/legend accuracy measurement. Serial replay elapsed2.474seconds over10samples; parent .NET peak working set60,203,008bytes excludes Tesseract subprocesses and is not whole-process-tree CPU/memory or gaming overhead. [Raw machine evidence](../../companion/fixtures/synthetic-evidence.json) and [fixture manifest/rights](../../companion/fixtures/manifest.json).

This evidence is insufficient for real automatic acceptance. Needed: owner-approved rights-cleared representative real result/negative regions across UI languages, resolutions, scaling and screen types; separate tuning/held-out corpus, field-specific missing/wrong/exact counts, classifierFP/FN, real successive-match deduplication and actual Windows-to-phone test. Until then the main automatic objective is unfinished. Mobile manual journal and accepted-record sync are independently testable.

## Packaging, privacy and license boundary

Self-contained win-x64 publish is a local unsigned folder; no installer, signing or Windows execution. Tesseract/English model/Leptonica are not bundled; installation requires a trusted separately obtained runtime and license review. Original project code MIT, .NET runtime/framework MIT with respective notices; test SDK MIT and xUnit Apache2. No paid SDK, background cloud service, telemetry, public API endpoint or provider credential. No AGPL tracker code. The system picker/ordinary OS capture does not establish EA or anti-cheat permission, and capture protection must never be bypassed.
