Implemented for **authorized local developer use**. Android and Linux-compatible shared checks passed, including real provider contracts and an opt-in Android UI/online/offline check. ## Functionality

- Shared Compose Profile screen links EA account name or stable UID with PC/PlayStation/Xbox selection; Switch supports UID only. PC explains EA vs Steam name. Successful name lookup resolves and persists UID/platform; subsequent refresh uses UID. Change/disconnect require no Apex Companion account or EA password.
- Ranked screen shows provider tier/division/RP, player/platform, available level/ladder metadata, source and last success. Unknown/new tiers survive as text; absent/invalid RP is unavailable, never zero. Provider responses cannot prove whether missing rank is private, unranked or incomplete; the UI states that uncertainty. Typed auth, missing-player, unsupported-platform, network, timeout, limit, server, schema and storage failures remain distinct.
- Independent manual RP and personal goals survive repository/app storage reopening. Users set/edit target RP/date, mark complete/reset, select manual or provider inputs, and see remaining RP, rounded daily requirement, percentage and original progress bar. Calendar dates use the current system timezone/DST. Completed goals stop requesting a daily gain. Target reached, expired/today, no deadline/current, negative input, stale provider and manual/live transitions are explicit. Progress measures gain from the saved baseline toward the personal target; provider updates never rewrite goals. No verified official season thresholds were available, so numeric targets work and rank presets are explicitly unavailable.
- `/predator` supplies dynamic RP cutoff and combined Master+Predator population for four platforms. It uses upstream update timestamps; successful retrieval does not make an old cutoff fresh. Cached values survive failures and omitted platforms in partial responses. Cutoffs do not guarantee placement and are not fixed rank goals. Widgets abstain from cross-platform or unassociated manual comparisons.
- Three Android Glance widgets show rank progress, ranked goal and Predator cutoff, source/time and freshness with compact/wide responsive layouts. Independent detail/platform preferences use Glance instance storage. They only read validated cached projections; opening/configuring instances makes no independent provider request. The existing unique WorkManager owns shared map/ranked synchronization and local freshness/midnight boundaries.
- Minimum settings cover the selected RP source, manual inputs, local date behavior and privacy. Broader v0.0 backup/import, Today/About destinations, appearance settings and complete polish are not marked implemented. No v0.3 observation history, match inference or sessions were added.

## Persistence, security and privacy

The existing AtomicFile/Foundation mechanism is extended, with separate private ranked, global Predator and unchanged map files. The actual v0.1 emulator map record was privately preserved during test isolation and restored byte-for-byte before normal startup. Only current normalized state is stored, not raw provider JSON or history. Repository writes precede successful state publication. Initialization rejects corrupt/future records without overwriting them, and independent global records survive private corruption. Android instrumented interrupted writes reopen the last committed record. Disconnect removes UID/name/snapshot while retaining independent manual/goal/global state. Android cloud/transfer rules exclude private profile records and credentials; iOS source excludes its private ranked record from backup.

Actual supplied credential bytes were absent from every ZIP entry of debug/release/test APKs and all scanned repository files. Release DEX lacks the private developer-file reader string; source release factory binds unconfigured map/ranked providers. Debug alone reads the deliberately provisioned app-private file. No API key in Gradle/resources/fixtures, logging plugin, credential-bearing redirect, public access setting, new analytics/ads/payment/account, proprietary image, restricted endpoint or backend was added. Public permission for Android+iOS and an approved sustainable credential-isolating architecture remain unresolved; developer success does not clear that gate.

Manifest permissions remain INTERNET, ACCESS_NETWORK_STATE, WAKE_LOCK, RECEIVE_BOOT_COMPLETED, FOREGROUND_SERVICE and the application-private receiver permission. No location, photo, microphone or contacts permission was added. Added source uses already selected Apache-2.0 Kotlinx/Ktor/AndroidX libraries; no comprehensive transitive vulnerability audit is claimed.
