# v0.1 iOS implementation handoff

**Status: Implemented — Not Verified.** All iOS compilation, tests, simulator/device runs, WidgetKit runtime and provisioning verification are explicitly deferred by the owner to final project stabilization. No Apple build or test command was executed for this milestone. Android/shared results do not establish iOS compatibility.

## Implemented source

- Existing Wizard app and framework build phase preserved. The existing `iosApp.xcodeproj` now declares a `MapWidget` native extension target, app dependency and embedded `.appex`, with a synchronized `WidgetExtension` source group.
- `MainViewController.kt` creates the common rotation repository, using the fail-closed unconfigured provider and a narrow Swift storage protocol. Shared Compose renders the same map interface as Android. The repository’s normalized cache and retry state are stored privately; cache-write failure is reported to common logic.
- `iosApp/RotationStorage.swift` atomically writes the private cache in Application Support and the sanitized KMP widget projection in the App Group. It requests `WidgetCenter` reload only after writing changed projection bytes. Write failures return through the native bridge so shared Compose can show a widget-publication warning. It does not share arbitrary private database paths, credentials or raw provider responses.
- Native WidgetKit/SwiftUI small, medium and large variants, independent per-instance App Intent playlist selection, last-sync/source labels and map end/start times. WidgetKit consumes the future entries already resolved by common `RotationWidgetCodec`; it does not infer map cycles or request network data. Unsupported/missing playlists, invalid schema, invalid times, missing/unprovisioned App Group and expired coverage render unavailable. Cached future transitions and freshness boundaries come from KMP.
- Widget taps open the Maps app via `apexcompanion://maps`. Widgets display end timestamps rather than promise second-accurate refresh. Timeline reload requests and the 15-minute disk reread request are advisory and controlled by iOS. No iOS background network schedule is registered while provider access is unconfigured.

## Configuration requiring final stabilization

- The Wizard’s iOS deployment target remains **18.2**. No minimum-target claim was tested.
- `TEAM_ID` is still empty. App/extension signing and provisioning must be configured by the maintainer.
- `APP_GROUP_IDENTIFIER=group.io.github.szymonbonkowski.apexcompanion` is **provisional**, not a registered or verified entitlement. Register/replace it for the selected team; both entitlement files and Info.plist substitutions must match.
- iOS provider access remains disabled (Android private developer verification is separate). The app contains no upstream API key and no deployed proxy. Real v2 response validation has now passed on the host/Android. A provider-authorized public credential-isolating topology remains an external dependency on both platforms; the iOS host deliberately stays unconfigured.
