# ADR0009 — Local Windows capture and truthful machine match provenance

Status: Accepted for implementation by explicit maintainer v0.4 instruction, 2026-11-03. Runtime/recognition approval is NOT implied.

## Context and scope conflict
The previous v0.4 specification, PRODUCT desktop exclusion and proposed ADR0006 prefer mobile manual/user-confirmed OCR. The maintainer now explicitly prioritizes automatic Windows match collection and local mobile sync. This extends the product with a separate optional PC utility; Android+iOS remain equal mobile targets. ADR0002 provider restrictions and ADR0003 RP interval semantics remain binding. ADR0006 human confirmation remains the screenshot-import policy; this ADR adds a distinct, evidence-gated machine acceptance path rather than relabeling automatic output as user confirmation.

## Decision
Separate .NET Windows companion: WinForms control window, Windows.Graphics.Capture through explicit system picker, selected application window only, visible capture border and immediate stop. No desktop recording, game process access, hooks, injection, drivers, packets, inputs or private endpoints. A protected/black/unavailable capture stops extraction without bypass. User choice is necessary but does not prove the selected window is Apex or that Apex permits capture.

Local Tesseract5 through a bounded process interface is the OCR direction (Apache2 engine; separate reviewed language/runtime dependencies), with normalized layout regions, field-level confidence, temporal consensus and an explicit persisted transition state machine. OS OCR was considered; its deployment/identity constraints complicate unpackaged distribution. PaddleOCR is a larger dependency/runtime; OverTrack is architectural background only and no AGPL code is incorporated. WGC is preferred over display-wide duplication and GDI for consent and selected-target semantics. The feasible minimum is Windows10 1903+ with supported GPU/API; actual exclusive fullscreen/borderless/windowed Apex behavior is unverified.

Frames remain transient; only allowlisted normalized candidates/events persist. Parser/layout version is durable. Missing fields remain null; results-observed UTC is collection time, not fabricated match duration/start time. Machine candidates REVIEW_REQUIRED are distinct from AUTO_ACCEPTED and USER_CONFIRMED records. MANUAL, SCREENSHOT and WINDOWS_CAPTURE remain separate original sources even after corrections. Original event identity/parser remain immutable; edited machine records retain their original normalized evidence for retry conflict detection.

Automatic acceptance requires demonstrated result classification, distinct transition, repeated compatible fields, schema validation and no duplicate. Shipped layouts are synthetic test fixtures; **automatic acceptance stays disabled** until rights-cleared representative held-out Apex data demonstrates field accuracy and false-positive/negative behavior. This leaves the primary zero-interaction objective unfinished until that gate and real Windows end-to-end tests pass. The mobile pipeline must still be implemented now.

## Local synchronization
Explicit opt-in listener on a selected private LAN IPv4 interface, HTTPS only. Out-of-band pairing supplies endpoint, SHA256 DER certificate pin, random256bit bearer credential, companion and player identity. Exact pin validation replaces public CA trust only for that specific endpoint; arbitrary certificates/redirects are rejected. Native DPAPI/Android Keystore/iOS Keychain protect secrets. No credentials in portable backup, logs or shared widgets. Revocation/unpair invalidates tokens; local unpair while offline explains separate PC revocation.

Foreground mobile pull is bounded, cursor-based and authenticated. Records+cursor commit atomically before acknowledgement. PC retains accepted data through disconnect/retry; stable IDs/event IDs prevent repeats and preserve user corrections. No instant/background delivery promise. No public bind, discovery, UPnP, cloud or provider API is introduced. See [wire contract](../contracts/match-sync-v1.md).

## Privacy, licensing and policy
No video/frame/screenshot retention by default, incidental OCR names discarded. Only the intentionally selected target is captured. No raw image syncing/telemetry. Dependency licenses and packaging notices must be reviewed before redistribution; no proprietary game imagery bundled. Microsoft's documented API does not grant EA/anti-cheat approval. EA rules remain applicable and no universal safety/approval claim is made. Relevant sources: [Microsoft capture](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture), [Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine), [Tesseract license](https://github.com/tesseract-ocr/tesseract/blob/main/LICENSE), [EA agreement](https://tos.ea.com/legalapp/WEBTERMS/US/en/PC/). Checked 2026-11-03.

## Validation and consequences
Portable synthetic state-machine/parser/serialization/HTTPS tests run on Linux; they do not prove Apex compatibility. Windows live ordinary-window then permitted Apex tests, resolution/layout measurements and successive-match phone sync remain mandatory. Android/shared checks are current-platform evidence. iOS source is Implemented — Not Verified under ADR0007; no Apple tooling in this milestone. Unsupported console capture remains unavailable; mobile manual entry works independently. No changes to existing Maps/Profile/Goals/History/Sessions/Predator/widgets.
